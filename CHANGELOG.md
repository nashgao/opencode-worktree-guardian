# Changelog

All notable public-surface changes are tracked here.

## Unreleased

### Added

- `guardian_hygiene` now measures every protected exclusion with bounded file, directory, and byte totals. Protected entries and goal postconditions explicitly report `assessment: "not-assessed"` and `cleanupAuthorized: false`; status warns instead of interpreting protection as proof that retained content is useful. Existing hygiene and exact-path deletion barriers are unchanged.
- Opt-in `goal.quarantineSessionResidue` clean completion now captures session provenance, requires a stable two-pass proof, and quarantines only eligible residue with non-overwriting same-device renames. `guardian_status` and `guardian_report_html` revalidate persisted proof read-only, while available items remain recoverable indefinitely through explicit token-gated `guardian_quarantine` restore or purge; Guardian never expires or purges them automatically.
- `goal.hygieneCompletion` now distinguishes cleanup authorization from goal completion. The default `authorized-cleanup` preserves legacy behavior, `no-unprotected-findings` rejects residual findings, and `no-unprotected-residue` additionally rejects reviewable candidates or incomplete inventory coverage. Goal plans expose `complete: null`; strict actionable plans can be `planned-partial`; strict apply can return `ok: true`, `complete: false`, and `status: "partial"` with bounded, digest-bound reviewable evidence.
- `guardian_goal` now accepts `allowedRemoteBranches`, an explicit per-call exact-name retention list on the resolved effective remote. Guardian normalizes and deduplicates the list, requires the same option set on plan and apply through the plan token, excludes listed remote refs from cleanup candidate discovery and strict extra-remote postflight blocking, and continues to evaluate a same-named local branch independently. The option does not persist policy, broaden deletion authority, affect unscanned secondary remotes, or allow unlisted remote branches.

### Changed

- Strict goal hygiene does not broaden deletion. Every mode auto-deletes only token-bound `known-cleanable` findings. Residual `nested-git` and `suspicious` findings require direct explicit review and are never auto-authorized. Dirty nested Git additionally requires direct `allowDirtyNestedGit`. Configured `protectedPaths` deny deletion and remain excluded from strict completion, but their bounded contents are visible as retention-unassessed inventory. `reviewableCandidates` remain scan-only inventory; `no-unprotected-residue` makes unresolved entries a completion failure without authorizing their deletion. TUI, skill, command, and invisible policy prompts require agents to inspect `complete` and `hygienePostcondition` instead of treating `ok` as desired-state completion.
- Protected inventory is authorization-neutral: changes to protected metadata do not stale `guardian_goal` confirmation. Directory handles, same-device identity checks, per-directory bounded reads, and capped protected-root results keep the read-only audit inside its repository and resource limits.

## 1.0.0 - 2026-08-08

### Added

- Operational-scope metadata and readable output now identify the effective remote, freshness, local and effective-remote branch counts, and disclosed secondary remotes. Status uses cached read-only refs, while final postflight uses the freshly fetched effective remote. Secondary remote names are disclosed but their branches are not scanned.
- Detailed final-postflight and cleanup evidence now uses bounded output lists with omitted counts for blockers, dropped commits, safety refs, preserved refs, candidates, results, and remaining blockers.
- Terminal session inventory now provides bounded, read-only recovery handoffs with exact `guardian_done cwd=... mode=plan` reattach and `guardian_delete_worktree mode=plan sessionId=... deleteBranch=true` cleanup commands. These handoffs do not mutate state or delete work.
- Remote branch cleanup now binds candidate identity, remote action, and presence state into the workflow token. Legacy missing phases are active; new reservations persist `pending-proof` before the canonical create-only raw-OID ref under `refs/opencode-guardian/remote-branch-cleanup/` and promote to active only after proof. Retry can create or promote. Active retirement preserves exact proof; pending no-ref retirement requires a strict descendant advance and preserves the remote branch without a safety ref. Absent reconciliation performs an empty-expectation leased CAS immediately before completion. Retirement-only work is counted, bounded with omitted counts, skips deletion, base sync, and final postflight, and requires a fresh plan.
- `guardian_status` now reports proactive distance from the locally cached base ref, making stale-base risk visible before a finish workflow begins.
- `guardian_hygiene` scan output now reports the weight of each reviewable candidate. Every `reviewableCandidates` entry carries `fileCount` and measured bytes, while `summary.reviewableTotalFileCount` and `summary.reviewableTotalBytes` cover the full inventory.
- `guardian_delete_worktree` now has an explicit `allowRedundantDirtyPaths` opt-in for direct plan/apply deletion of dirty target worktrees only when Guardian proves every dirty path already matches the fetched base tree. The default dirty-target blocker is unchanged. Successful apply creates the normal `safetyRef`, adds a `dirtySnapshotRef`, cleans only proof-approved paths internally, rechecks status, and then uses the existing non-force removal path.
- `guardian_finish` `merge-to-base` can now optionally preserve-then-clean a dirty primary repo worktree instead of dead-ending, gated behind the new `allowBaseWorktreePreserveReset` option (per call or via repo config, default `false`). When enabled, it snapshots the primary worktree's blocking dirt — tracked changes and untracked files, which `git stash create` would drop — into a recoverable `refs/opencode-guardian/<session>/base-worktree-preserved-dirt/...` safety ref, cleans only those paths through Guardian's internal path-scoped reset/clean routine that never touches the Guardian session worktrees under the worktree root, then repositions and fast-forward merges. The default stays fail-closed: without the opt-in, a dirty primary worktree still blocks. New preflight/report fields `baseWorktreePreserveReset` and `baseWorktreePreservedDirtRef` surface the action, and the preserved-dirt ref is recorded in session `safety_refs`.

### Changed

- **Breaking:** The zero-risk `guardian_status` verdict headline no longer reads `— clean, no risks detected.` It now reads `— no Guardian risk signals (Guardian scope only; not a repo-cleanliness claim).` Guardian's verdict answers whether anything matched Guardian's own rules, not whether the repository is clean, and the previous wording asserted the broader claim. Consumers matching on the old string must update. `guardian_hygiene` likewise prints `[WARN]` rather than `[GOOD]` when reviewable candidates exist.
- Reviewable hygiene candidates prioritize larger measured entries, then higher collapsed `fileCount`, with deterministic code-unit path ordering as the final tie-breaker. Standalone `guardian_hygiene` returns the full reviewable inventory; strict goal output stays bounded while its digest and confirmation token bind every omitted identity.
- `/guardian-hud` remains registered as a temporary command-compatible fallback. It shows the warning `Guardian HUD unavailable` with `The visual Guardian HUD is temporarily unavailable. Use /guardian-status instead.`, opens no dialog, and submits no prompt. Use `/guardian-status` for the normal Guardian status view.
- **Breaking:** Repository stash inventory is advisory by default instead of blocking every finish and cleanup operation. The misleading `allowStashIfUnrelated` key is retired and ignored; repositories that intentionally require an empty repository-wide stash inventory must set `requireEmptyStashInventory: true`. Guardian continues to inventory stashes and never mutates them. This public config/behavior change requires an explicit major-version decision before publication; this unreleased change does not update the package version.
- Command interception now defaults to audit mode. Raw destructive command classifications, direct file routing failures, route errors, and session/worktree mismatches are logged with `auditOnly: true` and allowed to proceed by default; set `commandInterceptionMode: "strict"` in `.opencode/worktree-guardian.json` to retain the previous hard-blocking behavior.
- Codex now matches OpenCode interception consequences: audit mode exits successfully with no blocking response, while strict mode blocks before mutation. Invalid interception configuration fails closed.
- `guardian_finish` `merge-to-base` now self-heals a clean primary repo worktree that is on the wrong branch. Under `allowMergeToBase: true` it creates safety refs for the primary worktree's original HEAD and the local base branch head, then repositions the primary worktree onto the base branch with `git checkout --no-overwrite-ignore` before the fast-forward merge. This removes the previous dead-end where the agent was blocked from positioning the base worktree but the tool refused to do it itself. A dirty primary worktree still blocks: Guardian never self-heals uncommitted base-worktree work. A base branch checked out in another worktree, a missing local base branch, a non-fast-forward merge, and post-merge push or remote-proof failures all fail closed with safety refs recorded.
- Wave 5C clarifies Guardian's cooperative concurrency boundary. Native and routed writers are mediated, while audit/strict interception is not OS-wide exclusion and arbitrary uncooperative or malicious same-UID writers are outside the guarantee. Opted-in ignored deletion now documents its token-bound removal-boundary recheck: observed drift blocks and requires a fresh plan, and a non-force removal failure rescans and preserves the worktree and branch while reporting the current ignored inventory.

### Fixed

- `guardian_finish`, `guardian_done`, and `guardian_goal` now block mandatory completion transitions when their final base observation is stale, divergent, or unverifiable.
- Public native and Codex Guardian contracts now expose `guardian_done rescue`. Rescue defaults to artifact-read-only token-bound planning, ignored-untracked residue blocks before recovery evidence, and only matching `mode: "apply"` with explicit `confirm: true` can reuse a cached token to materialize recovery evidence and clean bound paths. Cached tokens are not approval; primary unconfirmed apply remains no-refresh, and workflow/done-all unconfirmed apply rejects before discovery or fetch while confirmed apply refreshes and validates drift.
- Dirty `guardian_done` session commits now construct and token-bind an exact candidate tree in a temporary index. Tracked modifications, deletions, and renames continue to stage through `git add -u` even after their paths become ignored; genuinely new files use normal `git add`, and ignored-untracked files are never force-added. Exact-OID publication, branch compare-and-swap, index restoration, and public tracked-ignored regressions keep the reviewed tree stable through landing.
- Done-all now stops before later sessions when a failed child has already moved the remote base or the base cannot be re-observed, while proven unchanged-base child failures remain isolated. Direct and batch landing share the same exact fast-forward/two-parent-merge topology ratchet.
- Guardian-spawned Git and GitHub CLI processes now strip untrusted Git routing/configuration variables, disable interactive prompts and fsmonitor, use bounded deadlines, and ask Git to normalize signing-policy booleans before plumbing commits.
- Low-level `guardian_finish` now publishes an exact commit with a normal non-force push and configures upstream only after success. Expected-head leased publication remains limited to token-gated `guardian_done`; divergent remote feature history is preserved instead of rewritten.
- Retryable finish and worktree-deletion paths can reuse a planned safety ref only when it resolves to the exact expected commit and the matching session already recorded that ref at the expected head. Unrecorded or different-target collisions still block, and preserve, rescue, snapshot, and other recovery refs remain strictly create-only.
- Effective commit-policy inspection now fails closed when Git reports malformed or otherwise unreadable signing configuration instead of treating that failure as an absent key.
- Done-all now fetches the configured remote directly during transition observation, including valid remote names containing `/`; preserve-only finish collisions return structured blocked results without weakening create-only refs.
- Branch-only deletion retries retain their unique exact-head active session, reuse only its recorded same-OID safety ref, terminalize the session after success, clear stale failure fields, and deduplicate ref history. Redundant-dirty proof now treats pathspec-looking filenames literally.
- `guardian_status` no longer reports a repository as clean when the hygiene scan found unreviewed paths or failed outright. `computeGuardianVerdict` read eight signals and `summary.reviewableCandidateCount` was not among them, so paths Guardian scanned but no cleanup rule matched produced no signal and a repository holding hundreds of them rendered as clean. Separately, a failed hygiene scan zeroes every count and was detected only through `status.ok`, never `status.hygiene.ok`, so a crashed scan also rendered as clean. Both are now warn signals, and the failed-scan signal is ordered ahead of the findings signals so it cannot be masked by unrelated dirt.
- Guardian no longer records a session whose worktree resolves to a different git repository than `repoRoot`. When `context.directory` (which determines the `state.json` location via the git common dir) diverged from the resolved worktree across repositories, session records were written into the wrong repository's state and silently bypassed the `repoRoot`-keyed primary/protected poison guards. `guardian_start` and the `recordSession` writer now refuse cross-repo bindings, and `guardian_gc` detects such mis-homed active records under a new `foreign-repo` reason so they can be pruned.
- Interception now recognizes runtime aliases, configured and alternate executable paths, shell and stdin transport, dynamic ref destinations, and recovery-ref roots or descendants. GNU `env -iS` wrappers are parsed, while `env -P` remains unsafe.
