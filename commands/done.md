---
description: Plan or apply completion for the current Guardian session or an explicitly selected target
argument-hint: [mode=plan|apply] [primary=true] [sessionId=...] [branch=...] [all=true] [commitMessage=...] [confirm=true]
---

Use the `guardian_done` native tool for the implementation-done workflow. Run `mode=plan` first and inspect the selected lane, preflight facts, dirty files, and blockers. Do not stop at the plan when the user invoked this completion workflow: if the plan is safe, continue with `mode=apply`, `confirm: true`, and the same options. The plugin reuses a fresh matching internal plan token, so the user should not have to copy a token in normal command use.

Bare `guardian_done` targets the verified current Guardian session, even if the primary or another session is dirty. From any cwd, use an exact recorded `sessionId=...` or `branch=...` when the user has selected that session. An unbound primary checkout returns `needs-selection` without committing, publishing, landing, or cleaning. Stop there unless the user has selected a target; re-plan with that selector. Neither a sole dirty candidate nor a list of clean sessions grants authority to finish them.

Repository stash inventory is advisory by default and remains visible in the plan; Guardian never mutates it. Only repo config `requireEmptyStashInventory: true` makes a non-empty stash inventory block before session landing, primary publishing, or cleanup.

Use `all=true` only when the user expressly requests repo-wide completion. The `done-all` plan enumerates every active Guardian feature session and reports finishable, dirty, or protected sessions. Apply lands or already-landed-cleans each clean finishable session, skips dirty/protected sessions with exact next actions, fast-forwards the local base worktree from its tracked upstream when that upstream remote is trusted, and cleans safe redundant merged worktree/branch candidates while reporting dirty or protected leftovers. Inspect the readable summary, finishable sessions, skipped sessions, and confirmation evidence before `mode=apply` with `all=true` and `confirm: true`.

If the lane is `session-finish`, let `guardian_done` handle the whole session lifecycle. Active-session apply first checks whether the session commit is already reachable from the configured remote base; if it is, Guardian skips PR creation and performs token-gated stale worktree/local-branch cleanup. Otherwise it pushes, creates or reuses the PR, and uses repo config `pullRequestMergeMethod`: `merge` is the default, while linear-history repositories may opt into `squash`. Guardian binds the method into confirmation and requires the corresponding exact parent/tree transition proof before cleanup; it does not request GitHub CLI branch deletion. After a successful session land, Guardian also fast-forwards local base when safe and cleans safe redundant cleanup candidates and reports dirty or protected leftovers. Do not manually push, merge, clean, or remove worktrees.

Reattach can recover only the current non-primary worktree under the configured Guardian root when it has no active session owner. If the supplied `sessionId` is unknown and a different active session owns this worktree, stop on `blocked` (`session-not-found`); do not retry without the selector to finish that owner. A worktree left by a closed session can still be recovered if unowned. Check its path, checked-out non-protected branch, dirty-file gates, and finish preflight. A plan does not attach; confirmed apply may establish a recovery session and finish that worktree without its old session id.

Use `primary=true` only when the user expressly requests primary publication. For `primary-main-publish`, apply only after explicit user confirmation with the same explicit `commitMessage` and `confirm: true`; the plugin reuses the matching internal plan token when the plan is still fresh. The tool creates a safety ref before committing, pushes normally, proves the new commit is reachable from the configured remote base branch, then applies token-bound cleanup for safe redundant candidates while reporting dirty or protected leftovers. Do not raw-clean or bypass Guardian blockers.

For standalone cleanup of already-landed work, explicitly plan `guardian_finish_workflow`; bare `guardian_done` does not dispatch a cleanup-only lane. Inspect the targets and apply only after explicit confirmation with `confirm: true` and the matching workflow token. Local worktree and stale-branch cleanup still runs through `guardian_finish_workflow` and `guardian_delete_worktree`. Legacy missing-phase remote reservations are active. New remote reservations persist `pending-proof` before their canonical direct non-symbolic raw-OID ref under `refs/opencode-guardian/remote-branch-cleanup/`, then promote after proof; retry can create or promote. Active retirement preserves exact proof. Pending no-ref retirement requires strict descendant advance, preserves the remote branch, and has no safety ref to preserve. Absent reconciliation performs an empty-expectation leased CAS before completion. Retirement-only work is counted by done-all, bounded with omitted counts, skips deletion, base sync, and final postflight, and requires a fresh plan.

Never force-push, mutate stashes, delete unrelated remote branches, run raw worktree removal, run raw branch deletion, or bypass Guardian preflights. Full policy: `docs/adr/0001-guardian-safety-policy.md`.
